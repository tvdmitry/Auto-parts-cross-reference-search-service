# Подбор автозапчастей — Favorit Parts

Приложение для поиска производителей автозапчастей по артикулу и получения предложений с аналогами через API Favorit Parts.

**[Открыть сайт → tvdmitry.github.io/search-service/](https://tvdmitry.github.io/search-service/)**

Стек: **React, Redux Toolkit, JavaScript без TypeScript, Bootstrap, Vite**. Для локальной серверной версии используется Express.

## Как пользоваться

1. Введите артикул детали, например `01089`. После короткой паузы приложение загрузит производителей.
2. Выберите производителя, например `ASAM`.
3. Просмотрите предложения и аналоги: наименование, производитель, артикул, склад, цена и доступный остаток.

Таблица имеет ограниченную высоту и закреплённые заголовки. Сначала отображаются 20 строк; при прокрутке к концу добавляются следующие 20. Счётчик под таблицей показывает, сколько предложений уже отображено. Также доступна кнопка «Показать ещё».

**Вводить ключ не нужно.** В обоих запросах автоматически используется публичный ключ из примеров [документации API](https://lk.favorit-parts.ru/static/wsprice.pdf), страница 3: `00000000-0000-0000-0000-000000000001`. Формы ввода ключа нет; поиск доступен сразу после открытия или перезагрузки страницы.

Данные загружаются из реального API. Состав предложений, цены и остатки зависят от текущего ответа сервиса.

## Локальный запуск

Требуются Git и **Node.js 22.12+** с npm.

```sh
git clone https://github.com/tvdmitry/Auto-parts-cross-reference-search-service.git
cd Auto-parts-cross-reference-search-service
npm ci
npm run dev
```

Откройте адрес из терминала, обычно **http://127.0.0.1:5173**. Создавать `.env` для запуска не требуется: ключ из PDF подставляется автоматически и в локальном режиме.

### Личный ключ для серверной версии — необязательно

Чтобы использовать собственный ключ покупателя, скопируйте [`.env.example`](.env.example) в `.env` и замените значение:

```dotenv
FAVORIT_API_KEY=ваш_ключ_покупателя
```

После изменения `.env` перезапустите сервер. `FAVORIT_API_KEY` применяется только в локальном серверном режиме. Версия на GitHub Pages использует публичный ключ из [`src/api/config.js`](src/api/config.js).

Личный ключ из окружения не включается в JavaScript-сборку, Redux или браузерный URL. Не используйте для него префикс `VITE_` и не добавляйте `.env` в Git.

## Как работает поиск

1. После паузы в 500 мс при вводе артикула отправляется GET-запрос с `number` и автоматически добавленным `key`. Из массива `goods` собирается список уникальных производителей.
2. При выборе производителя отправляется GET-запрос с `number`, `brand` и `analogues=on`.
3. Таблица показывает исходные товары и вложенные `goods[].analogues`. Для каждого склада создаётся отдельная строка: наименование, артикул, производитель, склад, остаток и цена.

Цена берётся **только из `warehouses[].price`**, остаток — из `warehouses[].stock`. Устаревшее поле `goods[].price` не используется. Для позиции без складских предложений выводятся отсутствие цены и общий остаток `count` (в том числе нулевой); отсутствующие значения не подменяются нулями. Цены отображаются в рублях.

При изменении артикула очищаются выбранный производитель и предыдущие результаты. Запросы отменяются через `AbortSignal`; Redux дополнительно проверяет `requestId`, чтобы запоздалый ответ не заменил актуальные данные.

Обработаны: загрузка обоих этапов, пустой ответ, пустая структура товара из документации, отсутствие предложений, ошибки ключа и лимита API, сетевые и HTTP-ошибки, неверный JSON, тайм-аут. Для ошибок есть повтор запроса.

## Подключение к API

Спецификация: [wsprice.pdf](https://lk.favorit-parts.ru/static/wsprice.pdf), версия от 06.03.2023.

Используется HTTPS-адрес `https://api.favorit-parts.ru/hs/hsprice/`. Параметры кодируются через `URLSearchParams`, включая `#`, `&`, `+` и пробелы.

Документация API не предусматривает постраничную загрузку (`page`, `limit`, `offset` или курсор). Приложение получает предложения одним ответом и постепенно отображает их при прокрутке, без дополнительных запросов к сервису.

| Режим | Как отправляется запрос | Откуда берётся ключ |
| --- | --- | --- |
| GitHub Pages | Из браузера напрямую в HTTPS API; сервис разрешает CORS | Публичный ключ из `src/api/config.js` |
| Локальная разработка и серверная сборка | Через `/api/price` на том же сервере | `FAVORIT_API_KEY` или публичный ключ из PDF по умолчанию |

При разработке и предпросмотре прокси подключён как middleware Vite. Готовую серверную сборку обслуживает Express с тем же middleware. В обоих режимах API получает ключ в GET-параметре `key`.

## Сборка

### С серверным прокси

```sh
npm run build
npm start
```

Приложение доступно по адресу **http://127.0.0.1:3000**. `HOST` и `PORT` можно задать в `.env` или окружении процесса. Ключ также можно передать через окружение вместо `.env`.

`npm run preview` позволяет проверить эту сборку через Vite. Для постоянного размещения используйте `npm start` либо настройте `/api/price` на своём сервере. Сервер по умолчанию слушает только локальный интерфейс.

### Для GitHub Pages

```sh
npm run build:pages
npm run preview -- --mode pages
```

Сборка создаётся в `dist/` с базовым путём `/search-service/`. Локальный предпросмотр обычно доступен по адресу **http://127.0.0.1:4173/search-service/**. Эта версия работает на статическом хостинге и обращается к API прямо из браузера.

## Публикация на GitHub Pages

Исходный код находится в этом репозитории. Сайт публикуется через репозиторий [tvdmitry.github.io](https://github.com/tvdmitry/tvdmitry.github.io) по адресу **https://tvdmitry.github.io/search-service/**.

Чтобы опубликовать изменения приложения:

1. Отправьте изменения в ветку `main` этого репозитория и дождитесь успешного workflow **Check application**.
2. Откройте [Actions → Deploy application to GitHub Pages](https://github.com/tvdmitry/tvdmitry.github.io/actions/workflows/deploy.yml) в репозитории `tvdmitry.github.io`.
3. Нажмите **Run workflow**, выберите `main` и дождитесь успешного завершения публикации.

Workflow хостинга вызывает [`.github/workflows/pages.yml`](.github/workflows/pages.yml): получает актуальный код из `main`, запускает тесты, собирает приложение и публикует его в `/search-service/`. Push в репозиторий исходного кода запускает проверку CI; для обновления сайта выполните шаги публикации выше.

## Проверка

```sh
npm test
npm run build
npm run build:pages
```

Автоматические тесты проверяют подстановку ключа из PDF на обоих этапах, контракт API, кодирование параметров, цены и остатки складов, аналоги, нулевые значения, ошибки, тайм-аут прокси и защиту Redux от устаревших ответов. Они используют тестовые ответы и не обращаются к аккаунту Favorit Parts. Реальный поиск можно проверить с артикулом `01089` и производителем `ASAM`.
